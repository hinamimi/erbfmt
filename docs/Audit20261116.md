files. It is a fresh run against those revisions, not a claim that they are the
latest upstream commits. The formatter changes described here are unreleased.

## Regressions fixed

Five templates exposed two reproducible categories:

- Forem's `admin/users/show/profile/actions/_social_accounts.html.erb` and
  `liquids/_github_issue.html.erb`: whitespace after a multiline `strong` element
  was emitted as an extra leading space before adjacent ERB/text on the first
  pass, then removed on the second pass. Normalize whitespace at generated line
  boundaries while preserving the existing root-inline-fragment leading-space
  behavior. Existing inline-boundary regression tests still pass.
- Forem's `menus/show.html.erb` and OpenStreetMap's `shared/_pagination.html.erb`
  and `traces/show.html.erb`: generated method-chain continuation indentation
  was stripped as a common argument indent on the next pass. Preserve the
  continuation indent when reformatting a previously generated chain, including
  keyword arguments, block suffixes, hashrocket arguments, and nested calls.

The reduced examples live in `src/formatter/ruby_format_tests.rs`. They use
small generic helper calls instead of copying the full project templates.
No new Ruby syntax support was introduced.

## Fragment and cross-ERB boundaries

Enabling fragment tolerance accepted six additional Forem files:

- `admin/invitations/index.html.erb`
- `admin/users/show/flags/_index.html.erb`
- `articles/edit.html.erb`
- `credits/_pricing.en.html.erb`
- `credits/_pricing.fr.html.erb`
- `credits/_pricing.pt.html.erb`

Source/diff review shows unmatched surrounding markup in these cases: trailing
open containers or extra closing tags. Fragment tolerance deliberately permits
some of these structures; it does not establish that they were intentional
partials rather than malformed HTML. Keep the option disabled by default.

HTML that opens in one ERB branch and closes in another is still rejected in
both modes. A reduced contract test in `tests/json_contract.rs` fixes this
boundary. Supporting such templates would require a separate parser design and
rendering-safety review; fragment tolerance must not invent matching tags.

Raw text, contenteditable regions, inline punctuation, and non-foldable Ruby
remain covered by the existing preservation fixtures. This audit does not
recommend increasing the default formatter's acceptance on their behalf.

## Reproduce

After placing local checkouts under `external/rails-repos/`:

```bash
cargo build --locked
python3 scripts/audit-templates.py \
  external/rails-repos/forem/app/views \
  external/rails-repos/openstreetmap-website/app/views \
  --report /tmp/erbfmt-audit-default.json
python3 scripts/audit-templates.py \
  external/rails-repos/forem/app/views \
  external/rails-repos/openstreetmap-website/app/views \
  --allow-unbalanced \
  --report /tmp/erbfmt-audit-fragments.json
```

The script returns nonzero for non-idempotent output. Expected parser rejections
are recorded separately with file paths and messages. The JSON reports include
corpus revisions and all unstable paths so a later run can be compared without
checking out or rewriting third-party source inside tests.
