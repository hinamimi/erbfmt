# Development

This document is for contributors working on erbfmt itself. User installation
and CLI usage belong in the repository [README](../README.md).

## Toolchains

- Rust stable with `rustfmt` and `clippy`
- Ruby 3.4 and Bundler for the Ruby wrapper
- Node.js 24 and npm for the VSCode extension

The repository contains `.ruby-version` and `.node-version` for local version
managers.

## Repository Setup

Build the Rust CLI:

```bash
cargo build --locked
```

Install Ruby wrapper development dependencies:

```bash
BUNDLE_GEMFILE=packages/ruby/Gemfile bundle install
```

Install VSCode extension dependencies:

```bash
npm ci --prefix editors/vscode
```

## Verification

Run the Rust checks:

```bash
cargo fmt --check
cargo check --all-targets --locked
cargo test --locked
cargo clippy --locked -- -D warnings
```

Run version and Ruby wrapper checks:

```bash
ruby scripts/test/version_test.rb
ruby scripts/version.rb verify
BUNDLE_GEMFILE=packages/ruby/Gemfile \
  ERBFMT_BINARY="$PWD/target/debug/erbfmt" \
  bundle exec rake -f packages/ruby/Rakefile gem:verify
```

Run VSCode extension checks:

```bash
npm test --prefix editors/vscode
```

Common Rust and VSCode commands are also available as workspace tasks in
`.vscode/tasks.json`.

## Architecture

The formatter and linter engine remains in Rust. Ruby gems, npm packages, and
editor extensions are thin wrappers around the Rust binary and must not carry a
second ERB formatter implementation.

The core implementation is developed incrementally:

1. `src/syntax/erb/` separates HTML fragments and ERB tags.
2. `src/syntax/html/` tokenizes the HTML portions.
3. `src/syntax/template/` builds the mixed HTML/ERB structure.
4. `src/syntax/ruby/` parses the Ruby expressions that are safe to understand.
5. `src/formatter/` produces formatted output.
6. `src/linter/` reports configurable diagnostics.
7. `src/ignore/` parses shared ignore directives used by formatter and linter.

The `src/syntax/` tree owns parsing and tokenization. Formatter and linter code
should consume syntax structures from this tree instead of implementing another
parser locally.

Ruby expressions are still treated conservatively. `src/syntax/ruby/` provides
the first internal AST layer for simple helper calls, keyword arguments, arrays,
hashes, assignments, unary/binary operators, grouped expressions, modifier
`if` / `unless`, ternary expressions, ranges, splat arguments, constant paths,
percent literals, safe navigation, index access, and `do |param|` block suffixes.
`src/formatter/ruby_wrap.rs` now uses this AST layer to decide whether a Ruby
method call can be wrapped safely, while the final formatted text is still
generated by the existing conservative wrapping code.

## Implementation Baseline

The core includes mixed HTML/ERB parsing, conservative Ruby call wrapping,
configurable lint rules, formatter/lint ignore directives, and four mechanical
assist actions. The CLI exposes lint and assist JSON plus `--stdin-filepath`
for unsaved buffers. VSCode delegates formatting, diagnostics, and quick fixes
to that CLI.

`src/assist/` owns mechanical edit suggestions; `src/ignore/` owns shared
selector parsing and safe insertion metadata. Keep these decisions in Rust
rather than recreating them in editor wrappers. The public feature reference
belongs in the README and the dedicated configuration, lint, ignore, and editor
documents rather than in the roadmap.

## v0.3.4 Development Notes

These changes are prepared for v0.3.4. This section records implementation and
verification work; it is not a public release-status tracker.

### Formatter safety audit

A read-only follow-up audit covered 990 templates from the local Forem and
OpenStreetMap Website checkouts. Five files exposed two stability regressions:
inline-boundary whitespace changed on a second pass, and generated Ruby
method-chain continuation indentation was stripped on a later pass.

Reduced regression fixtures and fixes preserve the existing inline-whitespace
protections. All accepted templates are idempotent in both default and
fragment-tolerant modes. Parser acceptance and defaults remain unchanged;
idempotency alone does not prove equivalent rendered HTML.

See [Audit20261116.md](Audit20261116.md) for corpus revisions, counts, rejected
cases, and the `scripts/audit-templates.py` reproduction commands. Existing
[Forem](ForemAudit.md) and [OpenStreetMap](OpenStreetMapWebsiteAudit.md) audit
records retain their detailed findings.

### Quick Fix implementation

- Rust template nodes supply safe ignore insertion positions. Multiline
  attribute continuations, Ruby strings, raw-text contents, and syntax errors
  do not receive insertion suggestions.
- Consecutive ignore directives share the same following target line, allowing
  another rule or format ignore without displacing an existing suppression.
  Identical suggestions are deduplicated.
- The CLI supplies rule-to-assist associations instead of maintaining a second
  mapping in the extension.
- Document edits invalidate old diagnostics and trigger a 300 ms debounced
  refresh. Superseded work is cancelled; save, manual lint, and applied fixes
  refresh immediately.
- Applying a quick fix checks the document version again, including actions
  that were generated before a subsequent edit.
- Extension Host tests cover stale actions, composed ignores, Unicode/CRLF,
  and local edits. CI runs them against the Rust CLI under `xvfb-run`.

See [VSCode.md](VSCode.md) for the wrapper lifecycle and local test setup.

### JSON interface contract

Syntax diagnostics now provide structured locations. Lint JSON carries optional
ignore edits; assist JSON carries the corresponding rule ID and safe ignore
boundary metadata. [JsonInterface.md](JsonInterface.md) defines fields,
UTF-8 byte ranges, Unicode scalar columns, streams, exit statuses, and
compatibility expectations. [AI.md](AI.md) contains usage examples.

`tests/json_contract.rs` covers multiple-file output, severity and exit status,
syntax/configuration/I/O failures, excluded files, Unicode/CRLF positions,
composed ignores, and the unsupported cross-ERB-branch HTML boundary. A lint
ignore does not disable explicit CLI assist actions.

### Agent skill distribution

`skills/erbfmt/SKILL.md` is a self-contained instruction package discoverable
with `npx skills add hinamimi/erbfmt`. It uses the existing project CLI and does
not install a binary or implement a formatter in JavaScript.

Discovery and isolated copy installation were verified using skills CLI 1.8.1
for Codex and Claude Code. CI repeats this installation and compares the
installed files to the source skill. A disposable template project verified
read-only checks, scoped assist/format edits, clean lint, and idempotency.
GitHub installation requires the skill files to be pushed; release-pinned
installation additionally requires the matching tag. See [AI.md](AI.md) for
installation commands.

### Verification record

Local verification for this work passed 416 Rust tests (334 unit tests, 74 CLI
integration tests, 8 JSON contract tests), 16 Extension Host tests, the extension
checks, formatter/clippy checks, version checks, Ruby gem verification, and VSIX
packaging. The skill passed frontmatter validation and installation checks.
These counts describe the v0.3.4 preparation run; use the verification commands
above for the current checkout and check GitHub Actions separately after push.

uses Biome for formatting and linting. Build and package it with:

```bash
npm test --prefix editors/vscode
npm run package --prefix editors/vscode
```

binary resolution details.
